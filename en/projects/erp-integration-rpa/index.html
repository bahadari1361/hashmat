Connecting an ERP without an API to Microsoft 365

A trade ERP with no open API needed to feed data into Microsoft 365. Instead of promising too early, I designed a test protocol to support the decision.

Starting point

A lot of data lived in a desktop ERP for the trades that offers no open interface. The question was whether desktop automation could be a dependable bridge.

Approach

  1. Weigh the optionsCompared export functions, database access and UI automation with Power Automate Desktop.
  2. Test protocolConcrete criteria before committing to management: stability under UI changes, error handling, run time and maintenance effort.
  3. RecommendationA clear basis for decision instead of a promise that won’t hold up in production.

Outcome

  • A realistic picture of effort and risk
  • Measurable criteria for management’s decision

Technical details

RPA on desktop interfaces is sensitive to updates and screen changes. That’s why a test run with real data belongs before any commitment.
